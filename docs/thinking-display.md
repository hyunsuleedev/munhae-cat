# 채팅의 생각 과정 표시

Claude와 Codex CLI가 공개하는 thinking/reasoning 텍스트를 최종 답변과 분리해 표시한다. Gemini/Antigravity에는 이 표시를 제공하지 않는다. API 직접 연결이나 별도 AI 검사 호출은 추가하지 않는다.

- Claude: thinking delta를 즉시 전달한다. 메시지 ID와 블록 인덱스로 이미 전달한 길이를 기록해 완성 assistant 메시지의 중복을 제거한다.
- Codex: reasoning item ID별 누적 길이를 기록하고 started/updated/completed에서 새로 늘어난 부분만 전달한다.
- 공급자가 내용 없이 상태나 서명만 보내면 생각 과정 영역을 만들지 않는다.
- 생각 과정은 HTML로 실행하지 않고 이스케이프한 텍스트로 표시한다. 블록 완료 대기나 thinking 문자열 마스킹은 하지 않는다. 일반 답변과 구조화된 번역 결과의 기존 검증은 유지한다.
- 문서/프로젝트 채팅 및 문맥 노트 채팅에서 접고 펼칠 수 있다. 생각 과정은 현재 화면 세션의 표시용 정보이며 재시작 후 복원되는 대화 기록에는 저장하지 않는다. 다음 AI 요청의 대화 본문에도 넣지 않는다.
- 실행 중 표시량은 최대 200,000자다. 토큰 단위 수신 여부는 CLI와 모델에 달려 있다.

참고: open-design의 Claude 스트림 중복 제거와 Codex reasoning suffix 처리, Aside의 thinking/답변 분리 구조. 공급자별 기능 보장은 실제 출력 수신과 별개다.

## 검증 (2026-09-18)

- 설치된 Codex 0.155.0의 실제 JSONL에서 reasoning 본문 수신 확인. Claude Code 2.1.270은 시험한 요청에서 답변 스트림은 수신했으나 thinking 본문은 없었음.
- parser 테스트: 완료 전 즉시 전달, Codex 누적 item 중복 제거, Claude delta/완성 메시지 중복 제거, 빈 thinking 처리.
- desktop 테스트: 답변과 분리, 지원 공급자 제한, 문맥 채팅 이벤트 전달, HTML 이스케이프.
- 실제 Electron + 테스트 CLI 이벤트 재생: 실행 중 thinking 표시, 펼침/접힘, 답변 분리, 다음 채팅 중 이전 블록 유지 확인. 재생 검증은 공급자가 실제로 thinking을 보내준다는 보장이 아님.
- 런타임/desktop 타입 검사 및 desktop 빌드 통과.

## 문서·프로젝트 채팅의 중간 설명 (2026-09-18)

- 일반 채팅 요청은 `streamText`를 켠다. Codex의 각 완료된 agent_message와 Claude의 text_delta를 즉시 전달한다. Codex item ID와 Claude message ID로 재전송을 제거한다.
- 런타임의 outputText는 여전히 최종 답변이다. 중간 설명은 번역·표점의 구조화된 결과에 섞이지 않는다. 문맥 노트 채팅은 수정안 JSON 계약을 사용하므로 이번 일반 텍스트 스트리밍 대상에는 포함하지 않는다.
- 문서·프로젝트 채팅 화면은 텍스트, thinking, 도구 이름/상태를 수신 순서대로 표시한다. 완료 시 최종 답변과 중복되는 마지막 텍스트를 제거한다. 활동 블록은 현재 화면 세션에만 남고 최종 답변만 기존 대화 기록에 저장한다.
- 검증: 런타임 80개 통과/5개 live 관련 제외, 관련 desktop 19개 통과. 격리된 Electron에서 테스트 CLI 이벤트를 재생하여 완료 전 중간 설명 표시 및 완료 후 보존을 확인했다.

## 작업 과정 UI

- open-design처럼 thinking/도구 활동을 접이식 작업 과정으로 묶고 일반 설명·답변과 분리한다. 실행 중 기본 펼침, 완료 후 기본 접힘이며 직접 선택한 펼침 상태는 유지한다.
- thinking은 별도 색상과 아이콘, 생각 중/생각 완료 상태를 표시한다. 도구는 검색·자료 읽기·명령 실행·파일 수정 아이콘/제목과 상태를 표시한다.
- Codex item ID와 Claude tool_use ID를 전달하여 하나의 도구 행을 갱신한다. 동명 도구의 동시 실행과 완료 이벤트 재전송을 구분한다. 미완료 호출은 실행 종료 시 중단됨으로 표시한다.
- 도구의 상세 입출력은 전달하지 않으므로 UI에 가상의 상세 내용을 만들지 않는다. 표시는 실제 도구 이름과 수명 주기 상태에 한정한다.
- 문맥 노트 채팅도 같은 활동 컴포넌트/호출 ID 갱신을 사용한다. 수정안 JSON은 활동 텍스트로 표시하지 않는다.
- UI 검증은 격리된 테스트 프로젝트와 고정 이벤트 재생으로 수행했다. 실제 사용 앱은 테스트 CLI 환경 변수를 제거한 상태로 재실행했다.

## 번역 실행 활동 (2026-09-18)

- 번역과 후속 원문 연결 단계에서도 Claude·Codex의 실제 thinking 및 도구 상태를 AiRunView.activity로 전달한다. 두 CLI 요청의 도구 ID는 단계별로 구분한다. Gemini thinking은 계속 제외한다.
- 구조화된 번역 결과와 중간 text_delta는 활동에 추가하지 않는다. 검증된 결과의 기존 저장/적용 경로를 유지한다.
- 번역 팝업은 실행 전 자료 설정, 실행 후 진행 상태·접이식 작업 과정으로 전환한다. 활동 갱신 시 사용자가 선택한 펼침 상태와 스크롤을 유지한다. 실패·취소 후 설정으로 돌아가 다시 실행할 수 있다.
- 타입 검사, 빌드, 관련 테스트 23개 통과. 격리된 Electron/테스트 CLI로 설정→진행 전환, thinking 누적, 검색 완료 표시, 결과 JSON 비표시, 실패 복귀, 실행 취소를 확인했다. 사용자 문서에 실제 공급자 번역을 새로 실행한 검증은 아니다.
