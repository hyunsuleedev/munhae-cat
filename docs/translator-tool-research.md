# 전문 번역 도구 조사와 문해 적용안

조사일: 2026-09-08. memoQ 12.5 공식 도움말, OmegaT 6.1.0 공식 매뉴얼, RWS의 Trados 개발자 문서·공식 사용 안내, CCTI 공식 매뉴얼·스키마를 읽고 현재 문해 코드와 대조했다. 아래는 기능 조사와 구현 우선순위이며, 타사 프로그램을 직접 설치해 비교한 성능 시험이나 구현 완료 목록이 아니다.

문해에는 **전문 번역 → 구절 검토 → 근거를 붙인 재번역 → 변경 비교 → 확정** 흐름이 이미 있다. 가장 큰 개선 여지는 번역안을 더 많이 생성하는 데보다, 번역가가 용례를 찾고 남은 문제를 처리한 뒤 검토본을 전달하는 일을 짧게 만드는 데 있다.

## 공식 자료에서 확인한 상호작용

### memoQ: 용례와 점검 결과에서 작업 위치로 이어지게 한다

원문 또는 번역문을 선택하고 Concordance를 실행하면 프로젝트의 번역 메모리와 LiveDocs에서 표현을 찾는다. 원문·번역 동시 보기에는 자료 출처와 수정일, 가능한 경우 원래 문서도 표시한다. 양쪽 언어로 검색하고 반대쪽 표현으로 결과를 좁힐 수 있으며, 발견한 번역을 삽입할지는 사용자가 결정한다. [Concordance 공식 도움말](https://docs.memoq.com/current/en/Workspace/concordance.html)

용어 등록창은 선택한 원문/번역을 미리 채우며, 뜻풀이·사용 예·메모와 표기 변형을 기록한다. 유사도 매칭은 용어 QA에서 오탐을 만들 수 있다고 명시한다. [Create term base entry 공식 도움말](https://docs.memoq.com/current/en/Workspace/create-term-base-entry.html)

자동 QA는 용어·일관성·수·문장부호 등을 설정에 따라 검사한다. 사람이 해석과 문장을 평가하는 LQA와 자동 QA는 구분된다. [Edit QA settings 공식 도움말](https://docs.memoq.com/current/en/Workspace/edit-qa-settings.html)

QA 결과 목록에는 문서·행·문제 설명이 나오고, 항목을 열어 원래 문서에서 수정할 수 있다. 경고는 오탐으로 무시할 수 있으며 결과를 HTML 보고서로 내보낸다. [Resolve errors and warnings 공식 도움말](https://docs.memoq.com/current/en/Workspace/resolve-errors-and-warnings-tab.html)

외부 검토자는 양언어 표 RTF를 Word에서 수정해 돌려줄 수 있다. XLIFF 등 도구 간 전달 형식도 별도 지원한다. [Bilingual export wizard 공식 도움말](https://docs.memoq.com/current/en/Workspace/bilingual-export-wizard.html)

### Trados: 이전 번역의 재사용과 외부 검토를 별도 작업으로 제공한다

번역 메모리의 동일·유사 문장 제안과, 특정 단어/표현이 포함된 문장을 찾는 concordance는 다른 기능이다. 후자는 원문이나 번역문 선택으로 실행한다. 유사 문장 제안 역시 현 문맥에 맞게 사용자가 수정한다. [RWS 개발자 문서: Translation Memory Lookups](https://developers.rws.com/studio-api-docs/apiconcepts/translationmemory/performing_translation_memory_lookups.html)

공식 양언어 검토 안내는 Review에서 Word 검토본을 내보내고, 검토자가 번역 셀을 수정하거나 코멘트를 단 뒤, 다시 불러와 변경을 반영하는 절차를 설명한다. 원문·태그를 변경하거나 검토 중 원래 파일을 바꾸면 재가져오기 정합성이 깨질 수 있다. 이 안내는 2023-10-20 게시 자료이며 최신판의 모든 메뉴 배치를 보증하지 않는다. [Trados 공식 양언어 검토 안내](https://www.trados.com/jp/blog/bilingual-review/)

QA Checker와 Terminology Verifier를 번역 중 또는 번역 후 설정·실행하는 교육 과정도 공식 제공한다. 교육 페이지의 현재 본문은 자동 접근 확인 화면이었으므로 상세 사용 단계는 자료로 확보한 공식 과정 개요를 넘어서 추정하지 않았다. [RWS 공식 과정 개요 PDF](https://www.trados.com/media/images/trados-studio-level-2-qa-check-and-term-verifier-elearning_tcm234-220875.pdf)

### OmegaT: 검색·메모·용어를 작은 일상 동작으로 연결한다

텍스트 검색은 선택한 표현을 검색창에 넣으며 원문·번역·메모와 프로젝트/참조 자료 범위를 선택할 수 있다. 결과에는 원문과 번역이 함께 나오고 해당 항목을 열면 편집 위치로 이동한다. 검색 결과만 편집기에 표시하는 필터도 있다. 문장 단위 분절과 반복 문장 자동 전파는 끌 수 있다. [OmegaT Windows and Dialogs 공식 매뉴얼](https://omegat.sourceforge.io/manual-standard/en/chapter.windows.and.dialogs.html)

용어 패널은 현재 문장의 용어와 설명·링크를 제시한다. 직접 적는 Notepad와 파일에 포함된 읽기 전용 Comments를 구분하고, 메모가 있는 다음/이전 문장으로 이동할 수 있다. 같은 원문도 문맥에 따라 다른 번역을 둘 수 있다. [OmegaT Panes 공식 매뉴얼](https://omegat.sourceforge.io/manual-standard/en/chapter.panes.html)

Check Issues는 자동 점검 결과를 표로 표시하며, 항목에서 해당 문장으로 이동하거나 문제를 무시한다. 철자·용어·LanguageTool 검사는 선택적이다. [OmegaT Menus 공식 매뉴얼](https://omegat.sourceforge.io/manual-standard/en/chapter.menus.html)

### CCTI: AI 제안과 사람이 검토한 판단을 분리한다

용어사전 편집기는 주요 인명·지명·관직·개념의 뜻풀이를 AI 초안으로 만들고, 사용자의 검토본을 따로 보관한다. 검토한 내용은 뒤의 번역 생성에 참고 자료로 전달된다. 초안/검토본 전환과 비교도 지원한다. [CCTI 용어사전 공식 매뉴얼](https://app.vaquitalab.com/mediawiki/index.php?title=CCTI_Manual06)

스키마는 원문·표점·용어 초안·검토 용어·번역 초안·검토 번역을 구분하고, 의미의 범위를 해당 글과 일반 의미로 나눈다. 여기서 가져올 원칙은 **판단한 내용, 적용 범위, AI 입력에 실제 반영한 내용의 보존**이다. 이 구조만으로 번역 정확도 향상이 입증되는 것은 아니다. [CCTI 공식 스키마](https://app.vaquitalab.com/mediawiki/index.php?title=CCTI_Schema)

이번 조사는 기존에 검토한 CCTI 공개 사례 전체를 다시 수집한 작업이 아니다. 과거의 사례 관찰을 최신 구현 사실이나 통제된 품질 평가로 바꾸어 해석하지 않았다. CCTI의 단계 순서를 문해 사용자의 필수 절차로 복제할 근거도 확인하지 못했다.

## 구현 우선순위

아래는 자료와 코드 조사에서 도출한 문해 설계 제안이다. 타사 기능의 동일 구현이나 완료 선언이 아니다.

### 1. 작업 중 바로 쓰는 구절 검색과 양언어 용례

**사용 장면:** 번역가는 `太守`의 뜻을 결정하기 전에 이 프로젝트의 다른 글에서 어떻게 번역했는지 찾는다.

- 현재 문서의 찾기와 프로젝트 용례 찾기를 쉽게 연다. 원문/번역 범위와 현재 작업안/확정본 선택은 유지한다.
- 결과에 문서명, 원문과 대응 번역, 작업 상태를 보여준다. 해당 문장을 열거나 용례를 복사한다.
- 대응이 없는 구절은 원문만 보여주고 연결되지 않았음을 표시한다. 번역 전체에서 비슷한 문장을 임의로 짝짓지 않는다.
- 과거 번역에서 찾은 결과는 당시 버전을 보여준다. 현재 문서가 열렸다는 이유로 과거의 인용이 현재에도 존재한다고 표시하지 않는다.
- 출처·버전 식별은 상세 보기에서 확인하도록 하고, 기본 목록에는 해시·FTS·prefix 같은 구현 설명을 노출하지 않는다.

**완료 기준:** 반복되는 동일 한자와 보조평면 한자를 검색해 정확한 출현 위치로 이동한다. 미저장 번역문에서 찾은 결과와 저장된 프로젝트 검색 결과를 구분한다. 검색은 번역 내용을 바꾸지 않는다.

### 2. 검토할 문장으로 이동하는 점검 목록

**사용 장면:** 긴 문서를 확정하기 전, 원문 연결이 없는 부분이나 아직 판단을 적어 둔 부분을 하나씩 검토한다.

- 빈 번역, 연결 미생성·재검토 필요, 미대응 원문, 현재 버전의 코멘트, 명시적 보류 항목을 근거와 함께 모은다.
- 괄호·인용부호 등 기계적으로 확인할 수 있는 항목은 별도 후보로 보여준다. 원문/번역과 검사 이유를 같이 제시한다.
- 전체/문제 종류/코멘트 있음 필터와 이전·다음 이동을 제공한다. 가능하면 기존 문장 편집기를 그대로 사용한다.
- 의미상 정당한 차이는 번역가가 판단할 수 있어야 한다. 자동 점검 결과를 '번역 정확도' 점수나 '학술 검증 완료'로 표현하지 않는다.
- 번역이 바뀌면 점검 결과를 다시 계산하고, 예전 버전의 결과가 현 위치를 가리키지 않도록 한다.

**완료 기준:** 목록의 문장을 수정·저장하면 해당 항목과 개수가 새 상태에 맞게 갱신된다. 수동 확인한 대응은 AI 작업으로 덮어쓰지 않는다. 모든 경고를 해결하도록 강제하여 초안 검토나 내용 복사를 막지 않는다.

### 3. 앱이 없는 검토자에게 전달할 대조 검토본

**사용 장면:** 번역가는 지도교수나 동료에게 현재 번역과 질문·인용 출처를 함께 전달한다.

- 현재 작업안과 확정본을 명확히 선택한다. 검토본 표지에 문서명, 상태, 생성일을 적는다.
- 원문과 번역 전문, 실제 연결에 따른 문장 대조, 구절 코멘트와 출처를 포함한다. 길고 연결되지 않은 문장도 누락하지 않는다.
- 인쇄 가능한 HTML은 첫 구현으로 유용하다. 브라우저에서 바로 읽고 PDF로 출력할 수 있으며 문해 설치가 필요 없다.
- Markdown/JSON 같은 기존 출력은 보존한다. 이후 편집 가능한 DOCX와 교환용 TMX/XLIFF를 별도로 검증한다.
- 외부 수정본의 재가져오기는 단순 파일 업로드로 처리하지 않는다. 원래 문서·원문/번역 버전·문장 ID를 확인하고 변경 미리보기와 충돌 처리가 마련된 뒤 제공한다.

**완료 기준:** 실제 출력물을 열어 긴 한문, 한국어 줄바꿈, 보조평면 한자, 여러 원문 인용, 긴 ITKC 출처 링크, 이전 버전 코멘트 구분을 눈으로 확인한다. 코멘트는 검토 의견이며 출판 각주로 자동 번호 매겨 확정하지 않는다.

### 4. 판단을 재사용하는 가벼운 용어 동선

**사용 장면:** 한 구절에서 확인한 관직이나 인물 지시를 뒤의 번역에도 참고시키고 싶다.

- 편집기에서 용어 후보와 참고 내용을 작성한다. 현재 문서에만 적용하는 자유 문맥이 기본이며, 공통 사전 저장은 명시적 선택으로 둔다.
- 기존 공통 용어에는 원문 표현, 번역/독음, 메모, 사용 상태를 그대로 활용한다. 별도의 강제 개체 분류 작업을 추가하지 않는다.
- 다의어는 여러 해석을 허용하고 근거·문서 범위를 유지한다. 같은 한자라는 이유로 다른 시대의 인물이나 관직을 하나로 합치지 않는다.
- 번역 요청 미리보기에서 어떤 지식이 포함되는지 확인하도록 한다. 자동으로 생성한 잠정 뜻을 사람의 확정 판단처럼 전달하지 않는다.

**완료 기준:** 한 문서의 특수 해석이 다른 문서의 번역에 무조건 적용되지 않는다. 사람이 저장한 설명·출처가 재열기와 AI 전송 미리보기에서 유지된다.

## 고한문에 그대로 적용하지 않을 동작

- 반복 표현의 자동 전파: 같은 문자열도 화자·지시 대상·문헌에 따라 뜻이 다르므로 재사용 후보로만 제시한다.
- 숫자 문자열의 일치 강제: `一人`과 `1인`처럼 표기가 달라질 수 있다. 변환·생략을 이해하지 못하는 규칙은 오류가 아닌 확인 후보에 그쳐야 한다.
- 한문/한국어 길이 비율의 품질 판정: 주어 보충, 병렬 구문 풀이, 관직 설명으로 길이가 달라진다. 충분한 작품 표본 검증 전 기본 차단 규칙으로 쓰지 않는다.
- 표점과 문장 분절의 번역 전 강제: 현재 전문 번역과 선택적 표점 흐름을 유지한다. 문장 대조는 읽고 검토하기 위한 연결 정보다.
- 각주 검색 결과의 의미 자동 확정: 검색 일치와 해석 일치는 다르다. 대상 구절·설명·서지를 보고 번역가가 근거로 채택한다.
- QA 경고 0건의 학술적 승인: 원문 오독, 생략된 주어, 전고·인물 식별은 별도의 전문 검토가 필요하다.

## 이후 효과를 판단할 방법

동일 작품과 동일 번역안을 놓고 '의심 구절 찾기 → 근거 확인 → 수정 → 검토본 전달'에 걸리는 시간과 놓친 문제를 비교한다. 시·산문·관직 나열·인용문을 포함하고, 정확도 평가는 원문과 번역을 함께 읽는 전문가가 한다. 검색 속도나 연결 형식 검사의 통과를 번역 품질 개선 수치로 대신하지 않는다.

실용성 확인에는 번역가가 문서 하나를 끝까지 마칠 수 있는지가 중요하다. 저장·재열기, 검색 결과 이동, 수정 후 검토 목록 갱신, 인용 출처 보존, 실제 출력물의 가독성을 같은 작업 흐름에서 확인한다.
