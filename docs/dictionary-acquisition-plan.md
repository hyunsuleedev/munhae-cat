# 문해 사전 데이터 확보 분석

확인일: 2026-09-10. 현재 앱의 데이터·조회 코드를 확인하고, 공급사 공식 안내와 공개 배포 파일/API를 재검증했다. 이번 작업은 도입 분석이며 앱에 새 사전 데이터를 통합하지 않았다. 네이버 표본 확인은 사용자의 추가 요청을 반영했다.

**문해에는 한국어 전문 사전, 고전 원문 근거, 기본 문자 정보를 함께 제공하는 구성이 적합하다.** 무료 중국어 사전의 표제어 수가 커져도 조선 관직과 제도어의 뜻이 자동으로 채워지지는 않는다. 원문 글자·뜻번호·시대·출전·공급자를 보존하는 것이 우선이다.

우리말샘은 로그인 후 **내 정보 관리 → 사전 내려받기 → 전체 사전 내려받기**에서 Excel/XML/JSON을 제공한다. 표준국어대사전도 같은 유형의 경로로 전체 Excel을 제공한다. 대량 자료는 검색 API를 반복 호출하기보다 공식 전체 파일이 적합하다. 이번에는 공개 안내와 경로만 확인했으며, 로그인·전체 파일 생성·API 키 발급은 하지 않았다. 현재 코드의 국립국어원 연동은 검색 응답 위주여서 상세 조회와 뜻번호·출전 연결을 보완해야 한다.

**네이버 크롤링도 실제 표본으로 확인했다**

비로그인 브라우저에서 `目`, `提調`, `主簿`, `謚`의 검색·상세 JSON을 확인했다. `目`은 검색 미리보기 3개에 비해 상세에 15개 레코드가 있었고, `主簿`는 3개에 비해 5개였다. `謚`는 상세 5개 중 독음 구분 제목이 2개이므로 레코드 수를 뜻 수로 세면 안 된다. `主簿` 관련 단어는 통합 검색에 18개 중 5개만 나오고, 단어 목록 1쪽에 15개·2쪽에 나머지 3개가 나왔다.

따라서 허용된 수집을 구현한다면 **검색 → 정확한 표제어 및 공급자 구분 → entryId → 상세 → 독음별 뜻·용례·출처 보존**의 순서가 필요하다. 동일한 `大主簿`도 오픈마인드와 단국대의 서로 다른 항목으로 존재했다. 표제어만으로 중복 제거하거나 검색 미리보기를 전체 뜻으로 저장하면 손실이 생긴다. 일반 서버 요청은 HTTP 200인데 본문이 빈 경우가 있어 브라우저 표본 성공을 안정적인 전체 수집 성공으로 볼 수 없다. 전체 표제어 열거·호출 한도·장기 안정성은 미검증이다.

공개 개발자 목록에서는 한자사전 공식 API를 확인하지 못했다. [네이버 약관](https://policy.naver.com/rules/service.html)은 사전 허락 없는 자동화 수집·검색 등을 제한하고, [사전 도움말](https://help.naver.com/service/5609/contents/19816?lang=ko&osType=PC)은 콘텐츠 사용을 원할 경우 제공처에 사용 가능 여부를 확인하도록 안내한다. 판매용 앱의 전체 DB는 실제 제공처인 e-hanja·단국대와 공급 조건을 확인하는 경로를 우선 권한다. 네이버는 상세 페이지 연결과 사전 간 품질 비교 대상으로 활용할 수 있다. 소량 표본 성공이 오프라인 복제·재배포 허락까지 의미하지는 않는다.

**실제로 받은 자료의 범위**

**현재 프로그램에 연결할 위치**

기존 일반 사전 도구에는 `local`, `kostma`, `opendict`, `stdict` 조회 경로와 국립국어원 키 보관 처리가 이미 있다. 반면 새 구절 연구 보기는 `provider: "local"`로 고정되어 있다. 따라서 외부 자료를 확보한 뒤 먼저 구절 연구에서 공급자를 선택하거나 복수 사전의 결과를 비교할 수 있도록 연결해야 한다. 국립국어원 유효 키의 실제 호출 성공은 이번에 시험하지 않았다.

내장 데이터가 커지면 앱 실행 파일에 모든 JSON을 묶기보다, 내려받아 설치하는 사전 팩으로 분리하는 방안을 권한다. 읽기 전용 SQLite에 표제어·독음 검색 인덱스를 만들고 기존 Electron main 조회 서비스를 통해 제공할 수 있다. 프로젝트 SQLite에는 사용자가 채택한 뜻과 출처 기록만 남긴다. 공급 계약상 사전 전체를 오프라인 저장할 수 없는 자료는 공식 API 조회 경로를 유지한다.

각 항목에는 `공급원 / 판본 / 항목 ID / 원문 표제어 / 독음 / 뜻번호 / 의미 원문 / 용례 / 출전 / 원문 URL / 라이선스`를 분리해 보존한다. 지금의 `senses: {text, label}[]`만으로는 說文 본문과 단옥재 주석, 사전 뜻과 현대 번역, 고전 원문과 번역 예를 충분히 구별하지 못한다. `canCite` 하나도 화면 표시·프로젝트 저장·외부 AI 입력의 모든 권한을 대신할 수 없다.

`謚`를 `諡`로, `𠮷`을 `吉`로 치환해서 데이터를 합치지 않는다. 이체 관계는 검색을 넓히는 참조로 쓰고 원래 글자와 출전은 보존한다. 사전의 첫 번째 뜻을 현재 문장의 정답으로 자동 확정하지 않는다.

**권장 순서**

1. 현 번들의 누락을 평가할 실제 고문헌 표본을 만든다. 일반 다의어·허사·조선 관직·불교/성리학 용어·드문 자형으로 나누어 정확한 어휘 항목, 문맥에 맞는 뜻, 출전 제공 여부를 각각 평가한다.
2. 무료 자료는 우리말샘 공식 전체 파일의 한국어 어휘와 기존 위키의 출전 예문부터 보강 후보로 평가한다. CC-CEDICT는 영어 보조 뜻, 교육부 수정본은 중국어 원문 사전 팩으로 검토한다. 說文解字注·廣韻은 고전 자서 탭으로 분리한다.
3. 한국어 전문 옥편은 e-hanja에 최신 샘플과 DB 공급 조건을 확인하고, 한국 고유 어휘·용례는 단국대 협력 가능성을 함께 검토한다. 웹사이트에 적힌 대규모 수록량 대신 실제 표본으로 계약 대상을 평가한다.
4. 화면 조회, 선택 뜻의 프로젝트 보관/내보내기, AI 번역 근거 입력을 공급자별 허용 범위에 맞춰 연결한다. 업체 연락·API 키 발급·계약·구매는 이번 분석에서 수행하지 않았다.

원전 자체를 장기적으로 전산화하는 후보로는 공유마당의 [(증보)자전석요](https://gongu.copyright.or.kr/gongu/wrt/wrt/view.do?menuNo=200019&wrtSn=9082919)가 있다. 공식 만료저작물 표시를 확인했으나, PDF 원전을 교정된 현대 사전 DB로 만드는 전사·OCR·교정 작업이 별도로 필요하다. 중국어–영어 상용 자료는 [Wenlin 개발자 라이선스](https://wenlin.com/developers)도 공급 경로가 명시돼 있으나, 한국어 사전 확보가 우선인 문해에서는 후순위로 둔다.
