# 공통 지식 단순화

공통 지식의 입력·저장 경로를 문맥, 용어집, 불확실성으로 정리한다. 인물 관계나 역사적 유효 기간을 다루는 온톨로지는 도입하지 않는다.

## 사용 방식

- 인물·지명·관직 등의 배경, 해석 조건과 근거는 문맥 카드에 자유롭게 쓴다.
- 프로젝트 공통 문맥은 master에, 특정 권·문서의 문맥은 해당 node에 붙인다. 현재 문서에서 부모 방향으로 참조하며 형제 문맥은 자동 상속하지 않는다.
- 문서 저자는 자유 텍스트다. 비어 있으면 가까운 상위 문서의 저자를 사용한다.
- 시대(`period_text`)는 상속하고, 작성일(`date_text`)은 해당 문서의 직접값으로 유지한다.
- 용어집은 원문·번역 표현, 기본/허용/지양, 메모 중심이다. 기존 독음과 분류도 보조 정보로 보존한다. 용어 검사는 검토할 곳을 제시하며 문맥상의 정답을 판정하지 않는다.
- 기존 코멘트의 원문·번역 버전과 정확한 구절 연결은 유지한다. 코멘트를 프로젝트 전체에 자동 적용하는 기능은 추가하지 않는다.

## 스키마 v4 → v5

기존 migration 001~004의 내용과 checksum은 바꾸지 않고 `005_remove_people_places.sql`을 추가한다. 기존 SQL 파일은 옛 프로젝트를 식별하고 업그레이드하기 위한 이력이며, v5 데이터베이스에는 인물·지명 테이블이 존재하지 않는다.

사용자의 명시적 결정에 따라 기존 인물·지명 데이터는 삭제한다. 문맥 카드나 이관 artifact로 복사하지 않으며, v4→v5 변경만을 위한 백업도 생성하지 않는다. 오래된 v1~v3의 번역 저장 구조 변경에 필요한 기존 백업 절차는 별개다.

1. 문서에 직접 지정한 저자명만 `author_text`로 바꾼다. 상속받은 저자를 자손에 직접 저장하지 않는다.
2. 저자 FK·인덱스와 `persons`, `places` 테이블을 제거한다.
3. 외래 키 무결성을 확인하고 schema v5 기록을 저장한다. 실패하면 해당 transaction을 되돌린다.

새 API에는 `persons`, `places`, 해당 CRUD, `authorPersonId`가 없다. 직접 저자 입력·조회는 `authorName`을 사용한다. 원문·표점·번역·과거 AI 요청·일반 문맥·용어·코멘트 내용은 변경하지 않는다.

## 검색·AI

전용 인물·지명 필터를 제거하고 용어 필터와 일반 텍스트 검색을 유지한다. AI 요청에는 기존 및 새로 작성한 일반 문맥과 선택한 자료가 들어가며 요청 전문·manifest 기록을 유지한다. 삭제한 인물·지명 데이터를 AI 문맥으로 다시 생성하지 않는다.

문맥의 가까운 순서 정렬은 상충하는 역사적 주장을 자동 해결하지 않는다. 적용 조건과 판단의 불확실성은 본문에 명시한다.

## 검증 범위

검증은 기존 프로젝트 업그레이드와 재열기, 인물·지명 테이블 삭제와 복사본 부재, 기존 일반 문맥·원문·번역·코멘트 보존, 저자 직접값·상속·해제, 시대와 작성일의 범위, 검색·번역 요청·검토본 출력, Electron의 문맥·용어집 화면을 포함한다.

2026-09-10 로컬 검증에서 전체 타입 검사와 DB 테스트 154개가 통과했다. 이후 무백업 재개방 회귀 검사를 추가한 삭제 마이그레이션 테스트 4개도 통과했다. 데스크톱 빌드 및 테스트는 507개 통과, 5개 제외였다. 실제 Electron으로 기존 프로젝트를 v5로 열어 테이블 삭제, 추가 백업 부재, 외래 키 검사 및 quick_check를 확인했다. 문맥·문서 메타데이터·원문 버전·번역 버전·용어집·코멘트의 행 해시는 변경 전과 일치했다(문서 저자 컬럼은 변경된 이름을 대응시켜 비교). 문맥 기본 탭, 저자 자유 입력 필드, 용어 추가 창의 기본/허용/지양도 실제 화면에서 확인했다. 사용자 프로젝트에 시험용 지식이나 번역은 저장하지 않았다.
