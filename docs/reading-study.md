# 구절 연구

편집기의 **번역·검토 → 구절 연구**에서 현재 문서의 원문과 연결된 번역을 함께 읽고, 글자나 어휘의 사전 뜻을 확인·선택하며 독음·풀이 순서를 기록한다. 저장된 원문만 있어도 사용할 수 있다. 현재 원문과 연결이 확인되지 않은 번역은 연결된 번역으로 제시하지 않는다.

- 원문 또는 글자별 풀이에서 글자를 클릭한다. Shift+클릭으로 같은 연속 구절의 여러 글자를 선택한다(최대 100 유니코드 문자).
- 내장 사전의 뜻풀이 또는 문자 정보를 확인한다. **이 뜻 선택**을 누르면 사전의 원래 뜻·출처·저작자 표시·라이선스가 연결된다. 사용자가 저장하기 전까지는 초안이다.
- 독음과 선택적인 풀이 순서를 입력하고 **저장 / ⌘S**로 저장한다. 다른 글자·구절·보기·작업 단계로 이동할 때도 먼저 저장하며 실패하면 초안과 선택을 유지한다. 사용자가 자유롭게 쓰는 문맥 풀이 입력란은 제공하지 않는다.
- 기본 **행 맞춤**은 원문 글자·독음·기본 훈·선택한 뜻을 각각 같은 줄에 맞춘다. **카드**로 바꿔도 같은 정보가 유지된다. 기본 훈은 내장 사전의 첫 항목을 표시하며, 추가 항목 수와 전체 훈을 담은 툴팁을 제공한다. 선택하지 않은 사전 뜻은 ‘—’로 남긴다.
- 화면 너비에 따라 글자 줄이 나뉜다. 한 줄에 들어가는 저장 어휘는 함께 배치하고, 어휘 버튼으로 정확한 원문 범위를 다시 선택한다. **풀이 순서**는 입력한 번호로 화면의 글자만 정렬한다. 보기·정렬 전환은 미저장 초안을 유지한다.
- 오른쪽 패널에서 독음·풀이 순서·사전 뜻을 수정하고 저장한다. 긴 사전 결과는 패널 안에서 스크롤하며 저장 버튼은 하단에 유지된다. 연결된 번역은 글자별 풀이 아래에 표시한다.
- 관련 이체자를 눌러 사전을 조회해도 원문 글자와 주석 범위는 바뀌지 않는다. 문자 속성은 뜻풀이의 근거로 가져오지 않는다.

기록은 프로젝트 SQLite의 `reading_annotations`에 문서 ID·원문 버전 ID·유니코드 문자 범위 `[from, to)`와 함께 저장된다. 같은 글자가 반복되어도 위치별로 독립적이다. 보충 한자와 이체자 선택자를 포함하는 글자 묶음을 표시할 때도 원래 코드포인트 위치를 유지한다. 기존 기록 수정은 잠금 버전을 비교하며, 다른 창에서 수정된 내용을 덮어쓰지 않는다.

새 기록의 `gloss`는 빈 문자열이고 선택한 사전 뜻은 `citation_json`에 저장한다. 과거에 직접 작성한 `gloss`는 DB에 보존하며 독음·순서·사전 뜻을 수정해도 덮어쓰지 않는다. 현재 글자 카드와 어휘 목록에는 직접 쓴 풀이를 표시하지 않는다. 기존 컬럼을 삭제하거나 프로젝트 스키마를 바꾸는 마이그레이션은 없다.

원문 버전이 바뀌면 예전 풀이는 이전 버전에 보존되어 읽기 전용으로 표시된다. 현재 원문의 비슷한 글자에 자동으로 옮기지 않는다. 스키마 5 프로젝트는 첫 열기에서 일관된 백업을 만든 후 스키마 6으로 마이그레이션한다.

## 요청할 때만 실행하는 AI 분석

구절 연구 상단의 **AI 분석**을 누르면 현재 보고 있는 구절만 분석한다. 페이지 진입·글자 선택·구절 이동·일반 번역·채팅으로는 시작하지 않는다. 미저장 연구 기록이 있으면 먼저 저장하며, 저장 실패 시 분석을 시작하지 않는다. 기존 수동 사전 조회·뜻 선택·독음·순서 기록은 계속 사용할 수 있다.

설정된 AI CLI가 현재 구절·주변 원문·현재 연결이 검증된 번역·기존 연구 기록을 확인하고 내장 사전을 조회한다. 결과는 오른쪽 **AI 분석** 패널에 제안으로 표시된다. **접기 / 펼치기**로 긴 결과를 접고 수동 사전 조회를 계속할 수 있다. 사전 원문 인용과 **AI 해석**, 주의 사항을 구분하며, 개별 **채택**을 눌러야 독음·풀이 순서·선택한 사전 뜻이 `reading_annotations`에 저장된다. AI 해석은 분석 기록에 보관하고 사전 인용이나 기존 `gloss`에 넣지 않는다. 제안에 사전 인용이 없으면 기존 인용을 유지한다.

다른 구절·문서·작업 화면으로 이동하거나 페이지를 닫으면 진행 중 분석을 취소한다. 완료된 분석은 프로젝트의 `runs/reading-study/`에 최근 24건을 보관하며, 같은 원문 버전과 범위로 돌아오면 해당 구절의 최근 결과를 읽는다. 원문·번역·표점·문장 연결이 바뀐 결과는 다시 분석해야 한다. 연구 기록이 다른 창에서 바뀌었으면 기존 잠금 버전 비교로 채택을 거절한다. 위치가 달라진 글자에 결과를 자동으로 옮기지 않는다.

### AI가 호출하는 도구

분석 실행마다 발급한 로컬 권한으로 다음 세 도구만 해당 구절에 접근한다. 일반 번역·정렬 도구 권한과 분리되어 있다.

| 도구 | 입력 | 역할 |
| --- | --- | --- |
| `get-reading-context` | `{}` | 요청한 정확한 범위와 유니코드 코드포인트 위치, 문맥, 기존 기록 조회 |
| `lookup-reading-dictionary` | `{ "query": "之" }` | 요청 범위 안의 글자·어휘만 내장 사전 조회. 인용 가능한 뜻에 이번 실행의 `senseId` 발급 |
| `submit-reading-analysis` | 요약 및 위치별 제안 | 검증된 `senseId`만 사전 인용으로 연결해 제안 제출. 주석을 직접 저장하지 않음 |

세 명령 모두 `"$MUNHAE_NODE_BIN" "$MUNHAE_BIN" tools <command>`에 JSON을 표준 입력으로 전달한다. 제안은 `from`, `to`, `quote`, `reading`, `readingOrder`, `senseId`, `explanation`, `caution`을 포함한다. 앱이 정확한 원문 범위·글자 경계·출처·버전·내용 해시를 다시 확인한다. 성공적인 제출은 실행당 한 번이며 취소·만료 후 도구 호출은 거절한다. 이 제한은 앱 도구의 권한 범위이며 AI CLI 전체의 운영체제 접근을 제한하는 별도 샌드박스는 아니다.

어원 이미지와 검증되지 않은 사전 정보는 제공하지 않는다. AI 해석은 검토할 제안이며 출처가 확인된 사전 뜻과 구분한다.
