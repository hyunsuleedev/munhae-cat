# 번역가 작업 도구

2026-09-08. 편집기의 **번역·검토 → 번역 작업 도구**에서 사용할 수 있다. [타사 도구 조사](translator-tool-research.md)의 용례 검색, 검토 목록, 외부 검토 흐름을 고한문 작업에 맞게 적용했다.

## 일상 작업

1. **찾기·바꾸기**: 현재 문서의 원문 또는 번역을 그대로 찾는다. `⌘/Ctrl+F`로 열고 Enter 또는 화살표로 위치를 본다. 번역 작업안은 한 곳 또는 표시된 모든 일치를 바꿀 수 있다. 바꾸기 취소는 그 뒤 내용이 바뀌기 전까지 가능하다. 원문과 확정 번역은 이 도구로 바꾸지 않는다. 저장은 기존 번역 저장/`⌘/Ctrl+S` 흐름을 사용한다.
2. **내 번역 용례**: `⌘/Ctrl+Shift+F` 또는 버튼으로 연다. 선택한 구절을 검색어로 가져오며, 검색 버튼을 눌러 프로젝트의 저장본을 조회한다. 원문/번역, 현재 작업본/최근 확정본, 현재 문서만을 선택한다. 실제 저장된 대응만 나란히 표시한다. 연결되지 않은 부분은 전문 문맥으로 표시하며 의미상 대응을 추측하지 않는다. 현재 버전의 문장 결과는 해당 문장으로 이동하고, 이전 결과는 당시 인용을 유지하면서 현재 문서를 열 수 있다.
3. **용어 등록**: 확인한 원문 표현과 번역어, 적용 메모를 직접 적는다. 프로젝트 공통 용어이므로 이 구절에만 해당하는 판단은 구절 코멘트나 문서 문맥에 남긴다. 문맥에 따라 사용/기본 표현/사용하지 않을 표현을 구분한다. 같은 용어에 여러 번역어가 있으면 문맥 패널에 메모와 함께 모두 표시한다. 저장된 용어는 기존 AI 전송 자료 준비에 반영된다.
4. **번역 점검**: 미연결 문장·원문 범위, 용어집과 다른 번역어, 괄호·미상 표시, 현재 버전 코멘트를 모아 본다. 항목별로 좁히고 위치 보기로 이동한다. 미저장 편집은 현재 입력을 기준으로 점검하되 저장 코멘트의 좌표로 잘못 이동하지 않는다. 검사 결과를 번역 정확도 점수로 쓰지 않는다. 숫자 변환·의역 길이·동형이의어를 일괄 오류로 판정하지 않는다.
5. **검토본 출력**: 현재 저장본 또는 확정본, 현재 문서 또는 프로젝트 전체를 HTML/Markdown으로 출력한다. 원문·번역 대조표, 전문, 문헌 정보, 해당 번역 버전의 코멘트와 참고 링크를 포함한다. HTML은 앱 없이 브라우저에서 읽고 인쇄/PDF 저장할 수 있다. 이전 원문 기준 번역은 당시 원문을 출력하고 상태를 표시한다.

문장별 대조에는 원문·번역 구절 필터와 **원문 미연결 / 코멘트 있음** 필터가 추가됐다. 기존 대응 확인 필요 필터 및 이전·다음 문장 이동과 함께 쓴다. 편집 중인 행은 필터 때문에 갑자기 사라지지 않는다. 코멘트 위치는 번역 버전에 연결되므로 편집을 시작하면 코멘트 필터를 해제한다.

### 표점 대조와 구절 우클릭

- 문장별 대조 머리글에서 **원문 대응 구절 / 표점 대응 구절**을 전환한다. 현재 원문과 맞는 저장된 표점문이 있으면 기본으로 표시하고, 표점 버전과 작성 상태를 함께 보여 준다. 전환해도 입력 중인 번역은 유지된다.
- 원문 또는 표점 구절을 선택한 뒤 선택 영역 안에서 우클릭하면 **코멘트 달기 / 각주 검색**이 열린다. 선택만으로 창을 열지 않는다. 기존 코멘트 도구를 먼저 누르는 방식도 유지한다. 선택 후 Shift+F10, 메뉴의 방향키·Enter·Escape를 지원한다.
- 각주 검색은 선택한 원문 표현으로 한국고전종합DB 각주 대상 구절을 바로 조회한다. 추가된 표점 부호는 검색어와 저장 코멘트의 원문 좌표에 포함하지 않는다. 원래 원문에 있던 부호는 보존한다. 100자를 넘으면 더 짧은 구절을 선택해야 한다.
- 서책 보기의 원문에서도 같은 메뉴를 쓴다. 여러 대조 행에 걸친 코멘트는 위치를 누르면 서책에서 전체 범위를 보여 주고, 단일 행 코멘트는 필터를 해제해 해당 대조 행을 보여 준다.

이 추가 변경은 관련 테스트 55개, desktop 타입 검사·빌드를 통과했다. 실제 편집 탭에서 표점 전환, 코멘트 창, `提調` 각주 검색 결과를 확인했다. 임시 프로젝트의 Electron 편집기에서는 실제 마우스 선택·우클릭, 보조평면 한자 코멘트 저장·재열기, CRLF 보존, 여러 행 범위 이동, 미저장 번역 유지까지 확인했다. 이 편집기 검증용 복사본에서는 병행 개발 중인 계정 진입 화면을 제외해 편집 기능과 실제 preload/main/DB 저장 경로를 검사했으며, 로그인 흐름은 이 검증에 포함하지 않았다.

검색·이력 화면의 기본 표시는 문서 내용, 작업 상태, 변경 요약 중심이다. 식별자·해시 같은 기록 정보는 펼쳐 볼 수 있다. 기존 확정본 JSON/CSV/Markdown 출력과 백업은 프로젝트 홈에서 계속 사용할 수 있다.

## 구현 및 검증 범위

이번 변경은 DB 스키마를 바꾸지 않는다. 용례 검색과 검토본 출력은 프로젝트 원장의 읽기 전용 조회이고, 용어 등록과 번역 수정은 기존 저장·충돌 검사·버전 생성 API를 사용한다.

공식 memoQ, Trados, OmegaT, CCTI 자료 및 현재 프로젝트·편집·지식·이력·저장·AI 연결 코드를 조사했다. 실제 서비스에 유료 AI 생성을 다시 요청하거나 다른 상용 도구를 설치해 성능 비교하지는 않았다.

- 패키지에 맞는 런타임 검사: 440개 통과, 7개 라이브 검사 제외. 타입 검사와 desktop 빌드 통과.
- 격리 Electron 프로젝트: 양언어 용례와 정확한 문장 이동, 직접 용어 등록과 전송 자료 포함, 검토 항목 위치, 문장 필터 편집, 일괄 바꾸기·취소, 저장·재열기 확인.
- 161문장 검증 문서: CRLF와 보조평면 한자 보존, 문서 끝의 선택 구절까지 스크롤 확인.
- 실제 검토 HTML을 열어 대조표·전체 내용·각주 인용 링크·작업안 표기를 확인. 내보내기 검증에서는 저장 대화상자의 반환 경로만 임시 경로로 지정하고 renderer→preload→main→DB→파일 생성 경로를 실행했다.
- 960px 및 넓은 화면을 확인했다. 모든 쓰기 검증은 임시 프로젝트에 한정했다.

이 묶음은 검토 작업을 개선하는 구현이다. 편집 가능한 DOCX 왕복 검토, TMX/XLIFF 교환, 이전 코멘트를 현재 구절로 다시 연결하는 동작, 번역 이력 복원은 후속 개발 대상으로 남아 있다. 별도 설치본 서명·공증·배포는 수행하지 않았다.
