# 선택적 용어 검토

작업 순서: 원문 → 표점(선택) → 용어 검토(선택) → 번역·검토.
표점이나 용어 검토를 완료하지 않아도 저장된 원문으로 번역할 수 있다.

## 저장과 범위

`008_term_review.sql`은 기존 용어집을 보존하고 `term_entries`, `term_revisions`를 추가한다.
문서 ID가 null이면 프로젝트 공통, 값이 있으면 해당 문서 전용이다. 동일한 표기만으로
항목을 병합하지 않는다. `parentTermId`로 명시적으로 연결한 문서 풀이가 공통 풀이보다 우선한다.
공통 복사는 문서 풀이를 보존하며, 문맥 설명을 제외한 공통 후보를 새로 만든다.
공통 후보도 검토한 후 번역에 반영한다.

각 저장은 잠금 번호를 검사하고 전체 항목의 이력 스냅샷을 추가한다. 재생성은 새로운
AI 후보를 추가하며 기존 검토본을 덮어쓰지 않는다. AI 생성 모델과 실행 ID도 기록한다.
`sourceVersion`은 원문 버전 ID와 원문 head 잠금 번호를 결합한 검토 기준이다.
유효한 저장 표점본이 있으면 표점 버전 ID와 잠금 번호도 포함하고 표점본을 기준으로 추출한다.
표점본이 없거나 이전 원문의 표점이면 원문을 사용한다.
원문 또는 기준 표점이 변경되면 문서 항목은 재검토 전까지 자동 번역 자료에서 제외된다.
등장 구절은 선택된 기준 본문과 정확히 대조하며 start/end는 앱이 계산하는 UTF-16 위치다.

## 생성과 번역 반영

기존 CLI 설정을 사용해 버튼을 눌렀을 때만 추출한다. 제목과 상위 문서 정보, 원문,
또는 표점본, 기존 용어를 입력한다. 인물 식별·전고·다의어 등을 선정하며, 일반 문법은
해석에 영향을 주는 경우만 포함하도록 요청한다. 출처가 없으면 생성하지 않도록 지시한다.
AI의 사실 판단 자체를 자동 검증하는 기능은 아니다.

후보는 draft, 사람이 확인한 항목은 reviewed, 적용하지 않을 항목은 excluded다.
검토 상태와 해석의 확실성은 구분하며 uncertainty를 그대로 번역 자료에 전달한다.
전문 번역의 자료 스냅샷에는 현재 원문의 reviewed 항목 및 일치하는 reviewed 공통
항목만 추가한다. 기존 공용 glossary_entries도 계속 사용한다. 요청의 자료 해시와
내용에 포함되므로 번역 실행 당시 용어 풀이를 재현할 수 있다.

Claude/Codex에서 전달하는 thinking과 도구 이벤트를 진행 화면에 표시한다.
Gemini/Antigravity thinking은 표시하지 않는다. 취소 후 도착한 결과는 저장하지 않는다.

## Codex 용어 생성의 개인 지침 분리

신규 용어 생성 요청에만 `codexDisableUserContext`를 설정한다. 인증과 모델 설정을
유지하면서 실행 인자로 메모리 사용·생성, 플러그인, 사용자 developer 지침,
AGENTS.md 로딩을 제외한다. 개인 스킬 디렉터리를 읽어 SKILL.md 경로별로 끈다.
CLI 0.155.1 실측에서 디렉터리 경로로는 제외되지 않았고 SKILL.md 경로로 제외됐다.
스킬 본문을 읽거나 사용자 설정 파일을 변경하지 않는다. 기존 세션 재개에는 적용하지 않는다.
CLI 기본 지침과 일반 도구 정의까지 제거하는 기능은 아니다. Claude/Antigravity와
다른 작업은 기존 동작을 유지한다. 실제 실행 기록의 개발자 메시지에서 메모리와
스킬 목록이 없는 것을 검증했다. 전체 제한과 무응답 제한은 없고 사용자가 중지할 수 있다.

용어 생성은 번역과 동일한 자료 해석기를 통해 현재 문서, 상위 서책에서 상속된 문맥,
명시적으로 포함한 다른 문서 자료를 전달한다. 비활성·제외·상속하지 않는 자료는
동일한 규칙으로 빠지며, 적용 조건·예외와 코멘트의 원래 구절도 보존한다.
개인 Codex 메모리 제외는 문해의 문맥 자료 제외를 의미하지 않는다.
팝업의 ‘적용 문맥’에서 실행 시 참고할 자료를 확인할 수 있다.

## 참고 코멘트 분리 (스키마 9)

코멘트 재사용은 `comment_references`에 코멘트 ID·적용 범위·조건·보충 메모를 저장한다.
원본 코멘트는 매번 원래 구절·버전과 함께 조회한다. 신규 연결은 UI에서 기본 미적용이다.
원본 수정, 삭제 또는 기존 복사본의 내용 차이는 재확인 전 AI 적용을 막는다. 단순 포함
체크나 실행별 pin으로 이 확인을 우회할 수 없다. 연결 편집에서 확인한 원본 잠금 번호를
다시 검사하며, 삭제된 원본은 연결로 재확인할 수 없지만 독립 문맥으로 보관할 수 있다.

v8의 코멘트 출처 context_items는 원본 스냅샷과 비교해 같은 내용이면 빈 보충 메모로,
다른 내용이면 편집본 전체를 보충 메모로 이전한다. 기존 활성/상속/문서별 선택을 보존하고
편집 차이는 확인 필요로 표시한다. 기존 행은 삭제하지 않고 보관 처리하며 이전 요청의
provenance 기록도 유지한다. 스키마 변경 전 DB 백업을 만든다.

AI에는 문서 문맥과 참고 코멘트를 별도 항목으로 전달한다. 용어 생성 JSON에서는
`context`와 `referenceComments`, 번역·채팅에서는 `reference_comment` 자료 종류로 구분한다.
원래 구절·원본 코멘트·보충 메모·조건은 각각 명시한다. 이전 실행의 입력은 불변이다.
IPC의 기존 reuseCommentAsMaterial/updateContext 이름은 호환을 위해 유지하지만
comment_reference 대상은 별도 테이블의 저장/수정/해제 경로로 처리한다.

AI 용어 생성 팝업의 문맥·참고 코멘트 체크박스는 이번 요청에만 적용된다. `terms.start(documentId, excludedMaterialIds?)`가 제외 ID를 IPC/브라우저 브리지로 전달하고, main에서 현재 적용 가능한 자료를 다시 조회한 뒤 제외한다. 문서 설명은 선택 가능한 자료 경로로만 전달해 메타데이터를 통한 중복 주입을 막는다. 확인되지 않은 코멘트 연결은 선택할 수 없으며, 팝업을 새로 열면 문서의 기본 적용 상태로 돌아간다.

공통 용어집은 기본적으로 참고하되, 팝업에서 전체 참고를 끄거나 항목별 제외할 수 있다. 표점본(없으면 원문)에 표기가 실제 등장하는 기존 glossary 항목과 프로젝트 공통 term_entries만 같은 목록에 표시한다. 사용 제외된 새 용어는 후보에서 빠진다. `glossarySelection`을 IPC와 브라우저 브리지에서 검증하며 main에서도 현재 본문으로 다시 조회·필터링한다. 현재 문서의 기존 용어는 중복 생성 방지용으로 별도 전달한다. 공통 용어는 뜻이 확정된 정답이 아니라 기존 해석 후보이며, 문맥·메모·불확실성·실제 등록된 근거를 전달한다. 충돌하면 문서별 해석을 생성하고 공통 원본은 수정하지 않는다. 선택은 이번 요청에만 적용된다.

용어 선정은 표제어의 난도나 전고 여부가 아니라, 독해에 필요한 구체적인 식별·전문 의미 정보를 추가하는지를 기준으로 한다. 일반 어휘 풀이, 문장 전체의 감상·재진술, 가상의 축자역 오류만을 이유로 한 후보는 제외한다. 최소한의 온전한 표제어와 등장 구절을 분리하고, definition에는 해당 문맥의 뜻·대상을, contextNote에는 정의에 없는 적용 정보만 기록한다. 불필요한 contextNote·uncertainty는 null로 둔다. 제공 해제의 근거와 외부 원전을 검증한 사실을 구분한다. 동일 요청 안에서 후보를 추린 후 인물·방향·주체·사건의 일관성을 검토한다. 60개는 출력 안전 상한일 뿐 목표 개수가 아니다. 이 지침 변경은 이후 생성에 적용되며 기존 저장 항목은 자동 수정하거나 삭제하지 않는다.

문서 용어는 상세 편집창의 ‘용어 삭제’로 삭제할 수 있다. 삭제는 payload의 archivedAt 및 증가한 lockVersion을 저장하고 term_revisions에 이력을 남긴다. 공통 용어 삭제는 이 API에서 거부하며 연결된 공통 원본은 유지한다. 삭제한 항목은 모든 용어 목록과 이후 생성·번역 입력에서 제외되고, 오래된 편집창에서 저장해 되살릴 수 없다. 기존 요청 snapshot과 수정 이력은 보존한다. 삭제는 향후 AI가 같은 표현을 다시 후보로 생성하는 것을 영구 금지하는 기능은 아니다.

문서의 용어 화면은 왼쪽 저장된 표점본(유효한 표점본이 없으면 원문), 오른쪽 등장 순서의 용어 목록으로 구성한다. 원문의 하이라이트와 용어 목록은 양방향 선택되며 중첩 구절은 후보 선택기를, 복수 등장 위치는 이전·다음 이동을 제공한다. 현재 버전의 문서 용어는 저장된 occurrence 범위를 검증해 사용하고, 공통 용어 및 이전 버전 항목은 현재 본문에서 동일 표기를 찾아 표시한다. 이전 버전 항목은 재검토 필요로 표시하고 인라인 저장을 막아 상세 편집에서 현재 등장 구절을 재검토하게 한다. 원문 문자열과 이체자는 변경하지 않는다. 인라인 뜻풀이·문맥 저장, 검토 상태 전환, 삭제는 기존 IPC와 낙관적 잠금으로 처리한다. 추가 필드와 공통 용어 편집은 상세 편집에서 유지한다. 패널 폭이 좁으면 원문/용어 전환형 화면을 사용한다.


용어 생성 프롬프트는 인명·호·지명·작품명 중심의 짧고 온전한 표제어를 요구한다. definition에는 식별·뜻풀이를, contextNote에는 번역 선택을 바꾸는 문서 고유 용법과 근거를 둔다. 추정한 지시 대상을 확정 정의나 번역어로 치환하지 않는다. 단순 등장 상황·비교 역할·감상은 문맥 메모를 채우는 근거가 아니다.

AI 응답의 quotes는 참고 자료가 아니라 실제 등장 위치다. 생성 응답을 파싱할 때 표제어를 포함하고 현재 기준 본문의 연속 부분 문자열과 일치하는 인용만 중복 제거해 저장한다. 관련 문장이 잘못 추가되어도 유효한 인용이 남아 있으면 해당 후보를 저장할 수 있다. 유효한 인용이 하나도 없으면 표제어를 포함한 오류를 반환하고 전체 저장을 중단한다. 이체자·공백·표점을 정규화하거나 표제어만으로 대체 인용을 만들어내지 않는다. 사용자의 수동 저장과 DB 검증은 기존의 엄격한 검증을 유지한다.

후보 선정은 고유명사 식별과 장르·저술 성격·종교·제도 등의 핵심 전문 개념을 함께 검토한다. 집단 구성원은 집단명 설명만으로 충분하고 별도 쟁점이 없으면 개별 후보를 생략한다. 동일 대상의 별칭·별제도 독립적인 해석 정보가 있을 때만 분리한다. 최종 검토는 중복 제거 후 원문을 다시 보며 핵심 전문 개념의 누락을 확인한다. 특정 문헌의 정답 용어 목록이나 목표 개수를 프롬프트에 넣지 않는다.
