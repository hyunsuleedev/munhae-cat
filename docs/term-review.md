# 선택적 용어 검토

작업 순서: 원문 → 표점(선택) → 용어 검토(선택) → 번역·검토.
표점이나 용어 검토를 완료하지 않아도 저장된 원문으로 번역할 수 있다. 용어는 확정된 표점본이 있어야
만들 수 있다. 원문에는 문장 경계가 없어 위치를 정확히 정할 수 없기 때문이다.

## 저장과 범위

`013_document_terms.sql`은 기존 `glossary_entries`·`term_entries`·`term_revisions`를 백업 없이
삭제하고 `terms`, `document_terms`, `term_occurrences`, `term_candidates`를 만든다.

- `terms`: 표기 하나의 뜻 하나. 동명이인·다의어는 따로 두고, 별칭은 묶지 않는다. 여러 문서에 걸친
  인물 정보는 문맥 자료에 둔다. 뜻풀이·번역어 수정은 그 용어를 쓰는 모든 문서에 반영된다.
- `document_terms`: "이 문서의 이 확정 표점본에서 이 표현은 이 용어"라는 확정 기록.
- `term_occurrences`: 확정 표점본의 code point 범위. 같은 표점본의 같은 범위는 한 용어에만 속하므로
  한 문서 안의 동명이인도 위치별로 구분된다. 저장할 때 범위의 글자가 표기와 같은지 검증한다.
- `term_candidates`: AI가 만든 미확정 후보. 번역에 쓰이지 않는다.

`016_term_kinds.sql`은 용어 유형을 CCTI 스키마의 개체/개념/문법 구분에 맞춘다.

- 개체: person(인물), place(장소), period(시기), event(사건), object(사물), work(작품·문헌)
- 개념: concept(개념. 제도·관직·행정 용어를 포함한다), allusion(전고)
- 문법: grammar(문법: 허사·문형), idu(이두)

기존 office·institution은 concept로, expression은 grammar로 옮긴다. 저장된 행만으로는 이두를 구분할 수 없어서 expression은 모두 grammar가 된다. 사람이 확인할 곳은 유형에 담지 않고 문서별 판단의 confidence와 alternatives로 나타낸다. SQLite는 CHECK를 바꿀 수 없으므로 `terms`와 `term_candidates`를 같은 id로 다시 만든다. 이때 외래키 검사를 끈 채 실행하고 커밋 전에 전체를 검사한다. 작품·문헌의 번역어에는 책이면 《 》, 편·작품이면 〈 〉를 붙인다. 유형 목록은 DB의 `TERM_KINDS`가 기준이다. relay 번들용 MCP 사본과 화면 이름표는 테스트로 같은지 확인한다.

`017_term_confidence.sql`은 문서별 판단(`document_terms`, `term_candidates`)에서 `selection_reason`과 `uncertainty`를 없애고 `confidence`와 `alternatives_json`을 둔다. 번역 각주와 같은 구조다.

- confidence: 이 글에서의 판단을 얼마나 확신하는지. certain(확정), probable(유력), unknown(미상)
- alternatives: 실제로 경쟁하는 다른 해석·식별, 3개까지. 판별 근거가 있으면 괄호로 덧붙인다

사람이 확인할 곳은 확정이 아니거나 다른 해석이 있는 항목이다. 화면은 그 경우에만 '유력 · 다른 해석: …'을 한 줄로 보이고, 확정 판단에는 표시를 하지 않는다. 두 자유 문장 칸은 서로, 그리고 contextNote와 역할이 겹쳤다. 실제 출력에서는 같은 의심이 뜻풀이·이 글에서·번역어·불확실성 칸에 흩어졌다. 기존 uncertainty가 있던 행은 probable이 되고, 그 문장은 옮길 칸이 없어 사라진다. 선정 이유는 유형과 '목록에 있다는 사실'로 대신한다.

번역과 AI 채팅에는 현재 확정 표점본에서 확정한 용어만 들어간다. 다른 문서에서 확정한 같은 표기의
용어는 자동으로 적용하지 않고, 이 문서에서 확정해야 쓰인다. 수정 이력은 두지 않는다. 번역 요청의
자료 해시와 내용에 그때 쓴 용어가 남는다.

표점을 다시 확정하면 이전 표점본의 연결은 번역에서 빠지고, 확정 직후 그 사실을 한 줄로 알린다.
이전 연결은 다음 용어 생성의 참고 자료로만 남는다. 새 표점본의 후보를 모두 확정하거나 버리면 이전
연결을 삭제하고, 어느 문서에서도 쓰지 않고 어떤 후보도 가리키지 않는 용어를 정리한다. 이전
표점본에서 만든 미확정 후보는 재확정 시 삭제한다.

## 생성과 번역 반영

기존 CLI 설정을 사용해 버튼을 눌렀을 때만 추출한다. 제목과 상위 문서 정보, 문장마다 번호를 붙인
확정 표점본, 이 표점본에서 이미 확정한 용어, 참고 용어, 버린 후보를 입력한다. 인물 식별·전고·다의어
등을 선정하며, 일반 문법은 해석에 영향을 주는 경우만 포함하도록 요청한다. 출처가 없으면 생성하지
않도록 지시한다. AI의 사실 판단 자체를 자동 검증하는 기능은 아니다.

AI는 등장 위치를 문장 번호로만 답한다. 앱이 그 문장 안에서 표기를 찾아 정확한 위치를 계산하며,
위치를 찾지 못한 후보는 제외하고 개수를 알린다. 다시 생성하면 성공한 경우에만 남은 미확정 후보를
교체한다. 확정한 용어와 버린 후보는 유지한다. AI 생성 모델과 실행 ID는 후보와 확정 기록에 남는다.

후보는 확정하거나 버린다. 확정할 때 위치를 고르고, AI가 기존 용어와 같은 대상이라고 제안했으면
그 용어에 연결하거나 새 용어로 만든다. 버린 후보는 다음 생성에 "다시 제안하지 말 것"으로 전달한다.
검토 상태와 해석의 확실성은 구분하며 confidence와 alternatives를 그대로 번역 자료에 전달한다.

Claude/Codex에서 전달하는 thinking과 도구 이벤트를 진행 화면에 표시한다.
Gemini/Antigravity thinking은 표시하지 않는다. 취소 후 도착한 결과는 저장하지 않는다.

## Codex 용어 생성의 개인 지침 분리

신규 용어 생성 요청에만 `codexDisableUserContext`를 설정한다. 인증과 모델 설정을
유지하면서 실행 인자로 메모리 사용·생성, 플러그인, 사용자 developer 지침,
AGENTS.md 로딩을 제외한다. 개인 스킬 디렉터리를 읽어 SKILL.md 경로별로 끈다.
CLI 0.155.1 실측에서 디렉터리 경로로는 제외되지 않았고 SKILL.md 경로로 제외됐다.
스킬 본문을 읽거나 사용자 설정 파일을 변경하지 않는다. 기존 세션 재개에는 적용하지 않는다.
CLI 기본 지침과 일반 도구 정의까지 제거하는 기능은 아니다. Claude/Antigravity와
다른 작업은 기존 동작을 유지한다. 실제 실행 기록의 개발자 메시지에서 메모리와
스킬 목록이 없는 것을 검증했다. 전체 제한과 무응답 제한은 없고 사용자가 중지할 수 있다.

용어 생성은 번역과 동일한 자료 해석기를 통해 현재 문서, 상위 서책에서 상속된 문맥,
명시적으로 포함한 다른 문서 자료를 전달한다. 비활성·제외·상속하지 않는 자료는
동일한 규칙으로 빠지며, 적용 조건·예외와 코멘트의 원래 구절도 보존한다.
개인 Codex 메모리 제외는 문해의 문맥 자료 제외를 의미하지 않는다.
팝업의 ‘적용 문맥’에서 실행 시 참고할 자료를 확인할 수 있다.

## 참고 코멘트 분리 (스키마 9)

코멘트 재사용은 `comment_references`에 코멘트 ID·적용 범위·조건·보충 메모를 저장한다.
원본 코멘트는 매번 원래 구절·버전과 함께 조회한다. 신규 연결은 UI에서 기본 미적용이다.
원본 수정, 삭제 또는 기존 복사본의 내용 차이는 재확인 전 AI 적용을 막는다. 단순 포함
체크나 실행별 pin으로 이 확인을 우회할 수 없다. 연결 편집에서 확인한 원본 잠금 번호를
다시 검사하며, 삭제된 원본은 연결로 재확인할 수 없지만 독립 문맥으로 보관할 수 있다.

v8의 코멘트 출처 context_items는 원본 스냅샷과 비교해 같은 내용이면 빈 보충 메모로,
다른 내용이면 편집본 전체를 보충 메모로 이전한다. 기존 활성/상속/문서별 선택을 보존하고
편집 차이는 확인 필요로 표시한다. 기존 행은 삭제하지 않고 보관 처리하며 이전 요청의
provenance 기록도 유지한다. 스키마 변경 전 DB 백업을 만든다.

AI에는 문서 문맥과 참고 코멘트를 별도 항목으로 전달한다. 용어 생성 JSON에서는
`context`와 `referenceComments`, 번역·채팅에서는 `reference_comment` 자료 종류로 구분한다.
원래 구절·원본 코멘트·보충 메모·조건은 각각 명시한다. 이전 실행의 입력은 불변이다.
IPC의 기존 reuseCommentAsMaterial/updateContext 이름은 호환을 위해 유지하지만
comment_reference 대상은 별도 테이블의 저장/수정/해제 경로로 처리한다.

AI 용어 생성 팝업의 문맥·참고 코멘트 체크박스는 이번 요청에만 적용된다. `terms.start(documentId, excludedMaterialIds?)`가 제외 ID를 IPC/브라우저 브리지로 전달하고, main에서 현재 적용 가능한 자료를 다시 조회한 뒤 제외한다. 문서 설명은 선택 가능한 자료 경로로만 전달해 메타데이터를 통한 중복 주입을 막는다. 확인되지 않은 코멘트 연결은 선택할 수 없으며, 팝업을 새로 열면 문서의 기본 적용 상태로 돌아간다.

확정된 용어는 기본적으로 참고하되, 팝업에서 전체 참고를 끄거나 항목별로 제외할 수 있다. 이 문서의 이전 표점본에서 확정한 용어와, 다른 문서에서 확정한 용어 중 표점본에 표기가 실제 등장하는 것을 같은 목록에 표시한다(`terms.references`). 참고 용어는 뜻이 확정된 정답이 아니라 기존 해석 후보이며, 뜻풀이·근거와 출처 문서를 전달한다. 같은 대상이 확실하면 AI가 `existingTermId`로 연결을 제안하고, 표기가 다르거나 목록에 없는 ID는 무시한다. 선택은 이번 요청에만 적용된다.

용어 생성은 사람이 확인해야 할 곳을 고른다. AI가 혼자 판단하면 틀리기 쉬운 사실(덜 알려진 인물·서명·연대의 식별, 제도어, 이두, 별칭)과 번역의 방향을 정하는 해석(글의 핵심 개념어)이 대상이다. 먼저 글의 갈래를 파악하고 그 갈래에서 번역을 어렵게 하는 말을 중심으로 고른다. 공문서는 제도·행정 용어와 이두, 제화시는 화론·고사, 서간은 인물·서명, 경전은 핵심 개념어가 중심이 된다. 고르는 순서는 제도·전문 용어와 이두, 덜 알려진 식별, 이 글에서 다른 대상이나 뜻으로 쓰인 말, 핵심 개념어, 전고, 해석에 영향을 주는 허사·문형이다. 문형은 글 전체에서 1~2개만 고른다. 현대 한국어에서 같은 뜻으로 쓰이는 한자어, 뜻이 뻔한 낱자, 번역자가 사전 없이 아는 널리 알려진 인물·지명은 넣지 않는다. 예를 들어 평양은 넣지 않는다. 다만 별칭이나 핵심 개념어에 해당하면 넣는다. 20자 이하의 짧은 글만 낱말마다 다루고, 긴 글도 30개 안팎을 넘기지 않는다. 60개는 출력 안전 상한일 뿐 목표 개수가 아니다. 이 지침 변경은 이후 생성에 적용되며 기존 저장 항목은 자동 수정하거나 삭제하지 않는다.

문서 용어는 상세 편집창이나 목록 메뉴의 '이 문서에서 삭제'로 삭제한다. 삭제는 이 문서의 연결과 위치만 지우고, 다른 문서의 같은 용어는 유지한다. 마지막 연결이 사라진 용어는 함께 정리된다. 삭제는 향후 AI가 같은 표현을 다시 후보로 생성하는 것을 영구 금지하는 기능은 아니다.

사이드바에서 문서나 폴더를 삭제하면 그 노드와 하위 노드 전체를 보관 처리(`archived_at`)해 화면에서 숨긴다. 원문·번역은 패키지에 남는다. 확인 창은 삭제할 문서에만 연결된 용어와 코멘트가 있을 때만 '함께 삭제'를 묻고, 기본값은 남겨 두기다. 고르면 그 문서들의 용어 연결·위치·후보를 지우고 다른 문서가 쓰지 않는 용어를 삭제하며, 코멘트는 보관 처리한다. 다른 문서에서도 쓰는 용어는 연결만 빠진다. 고르지 않으면 용어는 쓰이는 문서 없이 용어집에 남는다.

문서의 용어 화면은 왼쪽 확정 표점본, 오른쪽 등장 순서의 용어 목록으로 구성한다. 확정 용어는 실선, 미확정 후보는 점선으로 표시한다. 원문의 하이라이트와 용어 목록은 양방향 선택되며 중첩 구절은 후보 선택기를, 복수 등장 위치는 이전·다음 이동을 제공한다. 후보는 '확정·다음'으로 빠르게 확정하거나 '고쳐서 확정'에서 위치·연결·풀이를 조정한다. 확정 용어의 인라인 수정은 뜻풀이(모든 문서에 반영)와 이 글에서의 풀이(이 문서만)를 저장한다. 원문 문자열과 이체자는 변경하지 않는다. 에디터의 '용어 추가'와 사전의 '용어 등록'도 같은 추가 대화상자를 연다. 용어집 화면은 확정된 용어를 행으로 나열하고(한자 표제어·번역어·한 줄 뜻풀이를 같은 크기로, 번역어와 다른 독음만 작게 덧붙임) 검사기에서 뜻풀이·번역어·근거를 수정한다. 검사기의 쓰이는 문서에는 문서별 등장 수, 이 글에서의 풀이, 표점본 버전이 나오고, 표점 재확정으로 번역에서 빠진 이전 버전의 확정은 따로 표시한다. '문서에서 보기'는 그 문서의 용어 화면을 해당 용어가 선택된 채 연다. 표기가 같은 다른 용어는 王建¹·王建²처럼 번호로 구별한다. 글자 크기와 줄 간격은 에디터의 원문 읽기 설정을 함께 쓴다. 용어집에서는 새 용어를 만들지 않는다.


모든 항목은 definition과 contextNote를 한 구절씩 채운다. definition은 다른 문서에도 보이는 일반 뜻이나 식별이고(40자 안팎), contextNote는 이 글에서 가리키는 대상이나 쓰임이다(35자 안팎). 핵심 개념어의 contextNote에는 이 글에서 택한 해석을 쓴다. definition과 translation은 다른 문서에도 보이므로 확정된 내용만 쓰고 추정 표현이나 괄호 설명을 넣지 않는다. 추정한 지시 대상을 확정 정의나 번역어로 치환하지 않는다. 프롬프트의 JSON 형식 예시는 테스트 원문에 없는 표현(汴京, 誠)으로 든다. 이 기준은 CCTI 위키의 용어집 예시와 한국고전번역원 번역 각주를 비교한 실험에서 정했다(`reports/ccti-demo-comparison/result.md`).

AI 응답의 sentences는 표제어가 이 뜻으로 등장하는 문장의 번호다. 모델이 센 글자 위치나 베낀 문장은 신뢰하지 않는다. 이체자·공백·표점을 정규화하거나 표제어만으로 다른 문장의 위치를 만들어내지 않는다. 사용자의 수동 저장과 DB 검증은 범위의 글자가 표기와 같은지 엄격히 확인한다.

후보 정리에서 집단 구성원은 집단명 설명만으로 충분하고 별도 쟁점이 없으면 개별 후보를 생략한다. 동일 대상의 별칭·별제는 독립적인 해석 정보가 있을 때만 분리한다. 붙어서 하나의 뜻을 이루는 표현과 제도 용어는 원문에 붙어 쓰인 단위로 쓰고, 문형도 원문에 연속해 나타나는 구절 그대로 쓴다. 최종 검토는 중복을 제거한 뒤 항목마다 '이 풀이가 없으면 번역할 때 틀리거나 막히는가, 또는 번역의 방향을 정하는 해석인가'를 확인한다. 특정 문헌의 정답 용어 목록이나 목표 개수를 프롬프트에 넣지 않는다.
